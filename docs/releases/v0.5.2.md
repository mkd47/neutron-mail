Neutron Mail 0.5.2 keeps the passwords and encrypted mail cache you already have, and builds address history in small batches so a large mailbox does not have to sit in memory all at once.

## Install or update (Fedora 44)

```sh
curl -fsSL https://raw.githubusercontent.com/mkd47/neutron-mail/main/scripts/install.sh | bash
```

The script downloads the RPM and `SHA256SUMS` of the latest release, checks the checksum and installs with `dnf`. Or by hand:

```sh
sha256sum -c SHA256SUMS
sudo dnf install ./neutron-mail-0.5.2-1.x86_64.rpm
```

Upgrading from 0.5.1 keeps your accounts, cache and settings. Account passwords and the cache key already stored in the keyring are still used, and an encrypted cache from 0.5.1 still opens with that key.

## Changed

- Address history for mail that was cached before that list existed is filled in small batches. A large mailbox no longer has to be loaded all at once. History that is already recorded is left as it is.
- Stored passwords and the cache key stay in the Secret Service under the same names. You do not need to enter them again after this update.
- Remote images are still fetched only when you ask, with the same certificate checks, and addresses on your local network are still refused.

## Known limitations

- Scheduled mail is sent by Neutron Mail itself: it goes out only while the app runs (or at the next start).
- The installer checks the download's checksum, which catches broken downloads; it does not verify a signature.
- Only an RPM for Fedora 44 (x86_64) is built.

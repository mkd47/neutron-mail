Neutron Mail 0.5.3 keeps the passwords and encrypted mail cache you already have, and stops trusting certificate intermediates that Mozilla and the major browsers already distrust.

## Install or update (Fedora 44)

```sh
curl -fsSL https://raw.githubusercontent.com/mkd47/neutron-mail/main/scripts/install.sh | bash
```

The script downloads the RPM and `SHA256SUMS` of the latest release, checks the checksum and installs with `dnf`. Or by hand:

```sh
sha256sum -c SHA256SUMS
sudo dnf install ./neutron-mail-0.5.3-1.x86_64.rpm
```

Upgrading from 0.5.2 keeps your accounts, cache and settings. Account passwords and the cache key already stored in the keyring are still used, and an encrypted cache from 0.5.2 still opens with that key.

## Changed

- IMAP and remote-image fetches use an updated Mozilla root bundle. emSign intermediates that are no longer trusted by Mozilla are rejected. A private CA you added in account settings is still trusted on top of that bundle.
- Stored passwords and the cache key stay in the Secret Service under the same names. You do not need to enter them again after this update. The comparison used when the keyring handles that secret material no longer leaks through timing.
- The desktop shell is Tauri 2.12.5. Window behavior, mail, and settings are unchanged.

## Known limitations

- Scheduled mail is sent by Neutron Mail itself: it goes out only while the app runs (or at the next start).
- The installer checks the download's checksum, which catches broken downloads; it does not verify a signature.
- Only an RPM for Fedora 44 (x86_64) is built.

First tagged release of Neutron Mail, a free desktop mail client for your own IMAP/SMTP server, built for Fedora 44 GNOME (Rust core, Tauri v2, Svelte 5). Not affiliated with Proton AG.

## Install (Fedora 44)

```sh
sudo dnf install ./neutron-mail-0.2.0-1.x86_64.rpm
```

Check the download against `SHA256SUMS` with `sha256sum -c SHA256SUMS`.

## Highlights

- **Mail:** IMAP over TLS or STARTTLS (certificates always verified), SMTP sending, IMAP IDLE push with a polling fallback, fast incremental sync (UIDNEXT/CONDSTORE), full-text search, unread badge and desktop notifications.
- **Safe rich HTML:** sandboxed message view, remote images blocked by default and fetched by the core behind an SSRF guard, link checking with tracking removal, attachment name and type safety.
- **Composing:** rich-text new mail, replies and forwards, drafts, signatures, contact autocomplete from GNOME address books.
- **Accounts:** provider profiles (Gmail, Outlook, 263.net, Alimail and manual), Mozilla autoconfig, OAuth2 sign-in for Google/Microsoft when built with client IDs.
- **Organizing:** folders (create, rename, nest, subscribe), drag-and-drop move/copy with undo, rules that run locally or on the server via Sieve/ManageSieve.
- **GNOME integration:** agenda strip and invitation replies via evolution-data-server, Notes and To-do with reminders.
- **Privacy at rest:** the mail cache is encrypted with SQLCipher, key and passwords in the system keyring.

## Fixes since the last builds from `main`

- Folder lists appear before large downloads start, sync progress is reported, and legacy GBK/GB18030 mail displays correctly; already-cached mail is re-indexed once in the background on first start, without delaying the window.
- A page of large messages on a slow connection no longer times out on every sync and stalls its folder.
- The remote-image guard also blocks IPv6 addresses that lead to private IPv4 networks (NAT64, 6to4, IPv4-compatible).
- The UI no longer reloads the folder and message lists for every downloaded page during a big first sync.
- Earlier audit fixes: mail safety and UI race fixes, bounded memory for image downloads, safer single-message deletes (UIDPLUS required), Sieve fallback for rules the server can't run.

## Known limitations

- A single message that takes longer than 60 seconds to download is retried on the next sync rather than completing.
- Only an RPM for Fedora 44 (x86_64) is built.

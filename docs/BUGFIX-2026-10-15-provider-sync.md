# Real-provider sync and encoding fixes

Refs #3. Base: a1da7a00d10992c66a755479c4d24a4f5f8428cd.

## Confirmed causes and changes

- Folder inventory was persisted one folder at a time immediately before its download. Later folders were absent from the cache/sidebar while an earlier large folder downloaded. Discover and persist every selectable folder first; emit discovery and per-page progress; refresh cached folders/messages while sync runs. Register event listeners before starting the first sync, and refresh metadata even when a completed background sync downloads zero messages.
- async-imap 0.12's LIST/LSUB name stream drops tagged completion status and can treat NO/BAD/EOF as a successful empty/partial list. Use the library's parsed response API with explicit matching tagged OK/NO/BAD and EOF handling. Reject incomplete LIST before cache reconciliation. Missing requested UID/body data in a rejected or incomplete message fetch also fails before advancing the sync checkpoint. An explicit LSUB rejection falls back to showing all LIST folders; connection/parse/time-limit failures still surface. Folder names, delimiters and selectability are available at debug log level; message content and credentials are not logged by this change.
- Downloads committed 500-message pages despite the wire fetch using 50-message chunks. Commit/report each 50-message page, newest first. A folder gets a five-minute limit; failure drops the uncertain connection and continues with a fresh one. A desktop account pass gets a fifteen-minute limit; saved pages survive and the next sync resumes through the cache diff. A manual sync waits at most thirty seconds for an account already being synced. Per-account locks keep one slow provider from blocking other accounts. These limits can produce a partial result for a very large first sync; the error tells the user to continue syncing rather than claiming completion.
- mail-parser was compiled without `full_encoding`; even correctly labelled GBK/GB2312, Big5 and Shift-JIS text was decoded lossily. Enable the library's multibyte decoders. For unlabelled or UTF-8-labelled malformed text, try strict GB18030 only if the bytes are invalid UTF-8 and decode without errors to CJK text. Respect other explicit charsets. Normalize malformed raw 8-bit display headers only; binary attachment bytes and stored raw mail remain unchanged. Encoding detection without metadata is inherently ambiguous.
- Existing summaries, previews and search text would otherwise stay corrupted. A versioned, transactional one-time reparse repairs cached summaries/search/address names, streaming one raw message at a time and retaining IDs, flags, raw mail, links and address-use counts. This can add work on the first launch after updating a large cache; subsequent launches skip it.

## Validation

Local core tests, full-workspace desktop clippy (all targets, warnings denied), Svelte checks, 25 frontend regressions and production frontend build passed before the workspace migration. New tests cover labelled multibyte MIME/headers, malformed raw GBK headers, unlabelled/mislabelled Chinese bodies, valid UTF-8/Western charset preservation, binary attachment preservation, old-cache repair/search, complete folder discovery before downloads, literal UTF-8 and modified UTF-7 folder names, NIL/dot delimiters, NoSelect attributes, LSUB rejection, LIST rejection/disconnect preserving cached folders, and rejected fetches preserving the old sync checkpoint.

The packaged desktop build, dependency audits and Fedora RPM installation check run in GitHub CI. NEUTRON_IT-gated live Dovecot/SMTP tests are not exercised by the local default test run. The reported real-provider mailbox and interactive Fedora/WebKit GUI still require acceptance testing; the report's encoding diagnosis was verified with synthetic fixtures rather than private messages. Non-selectable hierarchy containers remain excluded from the message-folder sidebar as before.
